# ComfyChair Media route extension (v1)

This is a **ComfyUI `custom_nodes` backend route plugin**, not a workflow node. `NODE_CLASS_MAPPINGS` is empty. It physically unlinks explicitly confirmed Input/Output regular image files. It never calls `DELETE /api/assets`, removes history, recursively deletes directories or deletes shared previews.

## Installation (administrator, separate approval required)

See **[INSTALL.md](INSTALL.md)** for a step-by-step Chinese installation guide (installing into `custom_nodes/`, environment variables, LAN mode, Android key setup, verification, uninstall). The English summary below is normative.

**This implementation task does not install/restart the live service or delete live files.** Back up files first. Extract the ZIP's `comfychair_media` directory into the actual ComfyUI `custom_nodes/` directory. The investigated deployment uses `/default-comfyui-bundle/ComfyUI`; verify this again at installation time. Python runtime dependencies are ComfyUI's existing `aiohttp` and stdlib. Linux only.

Configure the service process environment using a root/service-readable secret mechanism (not shell history, CLI arguments, logs or this document):

- `COMFYCHAIR_DELETE_SECRET`: independent random secret, at least 32 characters. Enter this in Android Settings → Server gallery → Deletion key. It is NOT the server login password.
- `COMFYCHAIR_AUTH_MODE`: explicitly `lan` for the simple one-key trusted-LAN mode below; default `proxy`.
- `COMFYCHAIR_PROXY_SECRET` (proxy mode ONLY): a different random secret, at least32 characters; only proxy/backend receive it.
- `COMFYCHAIR_TRUSTED_PROXY_IP` (proxy mode ONLY): exact immediate peer IP as observed inside ComfyUI (never caller-supplied X-Forwarded-For).
- `COMFYCHAIR_TOMBSTONE_FILE` (optional override, defaults to persistent plugin `missing.json`): absolute path to a persistent JSON journal in a private, trusted, service-writable directory outside input/output, e.g. a dedicated persistent service state directory. Parent directory must exist, must not be writable by users or contain symlinks. Never use a shared media directory.

Restart only after explicit authorization and a maintenance window. Missing settings, corrupt journal or unavailable/incompatible prompt queue make deletion unavailable. A late-bound queue adapter handles ComfyUI's custom-node loading before `prompt_queue` creation.

## Simple trusted-LAN direct mode (beta.6 / code60)

HTTPS/proxy was an earlier ComfyChair safety design, NOT a ComfyUI requirement. For a trusted LAN, set `COMFYCHAIR_AUTH_MODE=lan` and one `COMFYCHAIR_DELETE_SECRET` generated by a cryptographic random generator (at least32 characters, e.g. `secrets.token_urlsafe(32)`). Do not reuse a login password. LAN mode requires neither proxy secret nor trusted-proxy IP nor principal headers. No key is generated/enabled automatically. Missing/short key, invalid mode, corrupt journal or unavailable queue fails closed.

Android: Settings → Server gallery → Deletion key: enter that SAME key, enable **Trusted LAN deletion (allow HTTP)**, read the warning, then **Store securely**. That explicit save is consent to plaintext HTTP for this server and exact origin only. Changing hostname/port/protocol or selecting another server does not reuse its key/consent. Old beta5 server-ID-only credentials are deliberately not migrated; enter the key again. Empty key disables deletion. Ordinary server login auth is unchanged; no proxy internals appear in the app.

**Only use on a trusted private LAN; never expose to the Internet/untrusted Wi-Fi. HTTP sends key and operation tokens in plaintext, NOT encrypted. A network attacker can steal/replay the key and delete files. One shared key grants administrator deletion privileges, without per-user LAN roles.** Restrict network reachability administratively; this task changes no firewall/binding. HTTPS remains available but is not mandatory in explicit LAN mode; existing self-signed TLS policy is unchanged.

Journal defaults to `comfychair_media/missing.json`: a persistent trusted service-writable plugin directory needs no extra setting. KEEP this journal across upgrades; never overwrite/delete it when extracting a ZIP. Optionally set `COMFYCHAIR_TOMBSTONE_FILE` to a private absolute persistent path. Never use a user-writable/media tree. A non-writable journal causes item failure before unlink, not unsafe deletion.

## Optional proxy boundary (default `COMFYCHAIR_AUTH_MODE=proxy`)

The extra proxy requirements below apply ONLY to proxy mode, not LAN mode.

ComfyUI itself often has NO authentication. Optional proxy mode requires BOTH the dedicated deletion key AND a trusted authenticated/authorized reverse proxy:

1. Block all direct backend access using firewall/container networks. Bind backend only to a private proxy network. Configure TLS on the client-facing endpoint; app inherits the project's existing self-signed TLS policy, so administrators must control network/trust. Without explicit LAN consent Android refuses deletion credentials over nonloopback HTTP. Use HTTPS for this proxy mode.
2. Authenticate and **authorize media-deletion administrators** before forwarding `/comfychair/v1/media/prepare` and `/delete`. Ordinary gallery readers must NOT be allowed to delete. Basic authentication alone without a delete-admin allowlist is insufficient.
3. Strip/overwrite incoming `X-ComfyChair-Proxy` and `X-ComfyChair-Principal`. Inject proxy-only `X-ComfyChair-Proxy: <proxy secret>` and a stable authenticated administrator identity in `X-ComfyChair-Principal`. Do not accept caller-supplied identities. Forward `X-ComfyChair-Delete` unchanged. Do not log any of these headers or request bodies.
4. `/capabilities` exposes only protocol/auth mode and authorized availability, never user descriptors. `/missing` requires the same dedicated-key authorization as mutation, because it contains private media descriptors. Configure body limit 32KiB and rate limits at proxy too. Do not cache these routes. Do not redirect mutation routes.

No one-size-fits-all proxy config is shipped: installation requires adapting the actual deployment's auth provider/authorization rules and verifying header stripping, immediate peer IP and firewall isolation. Merely setting the secrets without this boundary is NOT a safe deployment. Do not configure a public peer IP or inject a fixed "admin" principal for unauthenticated traffic.

## Protocol

All endpoints under `/comfychair/v1/media`:

- GET `/capabilities`: `version:1`, `delete`, `max_batch:50`, `permanent:true`, `consistency:persistent_tombstones`, TTL120. `auth_modes:["lan","proxy"]`, `auth_mode` reports configured mode; `delete` is true only for the current authorized request. Safe discovery requires no credentials and never includes user metadata.
- GET `/missing`: `items:[{type,subfolder,filename}]`. Read-only persistent tombstones; SAME dedicated-key authorization required (403 otherwise). App sends it only with saved credential and transport consent. No-key readers retain ordinary browsing but cannot filter private tombstones, so stale asset/history references can remain visible.
- POST `/prepare`: exactly `{items:[{type:"input"|"output",subfolder:"",filename:"x.png"}]}`; 1–50 items. **Read-only on media files.** Returns unpredictable 256-bit operation token and indexed per-item ready/not_found/busy/invalid results. Snapshot binds descriptor and dev/ino/mtime_ns/ctime_ns/size; token also binds authenticated principal, expires in120s.
- POST `/delete`: exactly `{token:"..."}`. Executes each prepared ready entry once, with success/not_found/conflict/busy/invalid/failed results; partial success is explicit. Same token returns recorded results for10min from prepare, never repeats unlink, even if name was recreated. Operations are in-memory (max256); restart loses tokens and returns conflict rather than replay. Client has no automatic mutation retry; after ambiguous network loss inspect/refresh rather than prepare a new operation blindly.

Request stream bounded even with chunked encoding. Invalid batch/body →400, oversized →413, unauthorized/unconfigured →403, expired/unknown/wrong-principal token →409, capacity →503. Response has no absolute filesystem paths, stat identities, exception details, keys or workflow contents. Tokens must not be logged.

## File/queue safety and honest limits

- Input/output roots obtained from `folder_paths`. Descriptor rejects traversal, absolute/Windows paths, control chars, unsupported extensions and empty components. Walk EVERY root/subdirectory component with `dirfd + O_DIRECTORY + O_NOFOLLOW`, lstat final relative filename; regular files only, hardlinks refused. No recursion. Extension identifies supported image filenames, not a full decoder/content validation.
- Hold **the actual ComfyUI prompt queue mutex** while checking queue and stat/journal/unlink. Refuse whenever ANY pending/running job exists, including custom nodes with unknown references. Do not call queue helpers that reacquire a nonreentrant mutex. New enqueue/get activity using that mutex cannot interleave with this operation. This conservative guard is intentionally broader than exact reference analysis.
- **NOT race-free against external writers/readers, other plugins bypassing prompt queue, filesystem renames or uncoordinated upload endpoints.** POSIX unlink-by-name lacks an atomic inode-conditional primitive; final snapshot check mitigates but cannot eliminate the last check→unlink replacement window. An administrator MUST exclude external mutation of these media trees during deletion (maintenance/exclusive access). Already-open external readers may retain unlinked data. Never advertise universal TOCTOU elimination.
- Asset API source investigation found reference deletion does not delete physical content. No verified stable missing-content mutation API was available, so this version does NOT modify the assets DB. Instead durable tombstones hide exact Input/Output descriptors in this ComfyChair client. Other ComfyUI frontends/history/assets may continue showing stale records. No shared previews are removed. Cached lists can briefly appear before fresh revalidation; successful local deletes immediately hide selected tiles and invalidate that source's list namespace plus exact thumbnail keys.
- Tombstone intent is fsynced BEFORE unlink and snapshot checked again. If crash/unlink failure occurs after journaling, a still-existing file may remain hidden. Recreating the same filename remains hidden. Administrator must reconcile exact paths and run the deployed version's supported asset reindex, then edit/reset journal during service downtime after backup. This task does not invent or execute a reindex command. Cap5000 tombstones, no automatic purge; stop/maintain before capacity is reached.
- Service state directory is trusted; do not place its journal through user-writable parent paths. Admin-owned namespace and exclusive maintenance are required in addition to no-follow media traversal.

## Android behavior

Settings → Application → Server gallery is a distinct page, not a source picker. It reuses existing source discovery, 50-item pagination/sparse-page guard, 3-column grid, sampled bounded HMAC-scoped cache, search/sort (assets only; legacy limits remain), refresh and full-image download-on-tap. Full viewer: filename, decoded dimensions, actual downloaded encoded bytes, zoom/pan, save PNG to phone, save material (existing library JPEG semantics), use as source slot1 via a one-shot process-local identity-checked capability; no bitmap Intent. Source navigation returns to Image-to-image; it does not submit a workflow or silently enable extra slots. Source is an imported local bitmap, not claimed as direct original-file reuse. Existing picker remains.

Long press in BOTH pages enters selection only with authorized capability. Count, select-loaded(max50), clear/cancel, irreversible confirmation with source/count, per-file localized results. Dedicated key uses Keystore EncryptedSharedPreferences with **no plaintext fallback**, excluded from OS backup/transfer; key not retained in saveable UI state. Original selected editing bitmaps, materials and comparison snapshots are never cleared by remote deletion. Direct Input reuse still HEAD-checks and only404 falls back to immutable upload.

## Tests

Run `python -m pip install pytest pytest-asyncio aiohttp`, then `python -m pytest server/tests -q`. Tests use only isolated temporary media and aiohttp test servers, never the live deployment. JVM tests cover protocol/auth headers/no redirects, result validation, selection gating, cache invalidation and route/viewer/source wiring; existing directInput/cache/pagination tests retained. No-device builds cannot prove rendered Compose gestures, installation, Android Keystore, codecs or post-R8 runtime behavior.
